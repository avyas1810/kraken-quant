# Milestone 1: repository audit, portfolio targets and read-only Kraken

Run `python -m kraken_quant.milestone1 audit` to inspect Git state, required interfaces and credential exclusion without reading notebooks, strategy results or secrets. A tracked `.env`, missing interface or unignored `.env` fails the check. This is an interface inventory, not a security certification.

`PortfolioTarget` is an immutable version 1 strategy output: decision identity, venue-labelled Instrument (asset/base and quote), signed target weight in [-1, 1], timezone-aware decision timestamp, exclusive validity deadline and typed `NormalExit`. Nonfinite/boolean weights, unsupported versions, inverted validity and malformed exits fail validation. Instrument support is supplied by the caller, never inferred from a research universe. Negative weights are research instructions; existing production long-only and gross-exposure controls still apply.

`NormalExit("next_target")` holds the desired target until a replacement instruction arrives. `NormalExit("at_time", exit_at)` requests flattening at or after exit_at, which must lie strictly inside instruction validity. Expiry rejects instructions; it does not authorize liquidation or order submission. Callers must schedule evaluation for timed exits and refresh instructions before expiry; the contract is not a background scheduler or emergency risk control.

`PortfolioTargetAdapter` wraps a `portfolio_targets(context)` strategy for the existing `StrategyPipeline`. It preserves `None` as hold quantities and uses existing `validate_weights` for gross and optional long-only policy. Explicit batches omit instruments to zero weight, matching existing semantics. Duplicate instrument targets fail. Existing target-weight strategies remain compatible. The original quantity-based `TradeIntent` remains as a legacy compatibility interface; new strategies should emit portfolio targets.

`target_execution.size_target` calculates desired base quantity as target_weight * current account equity / current market price, subtracts current holdings, and returns the existing risk `OrderIntent` (or None for no change). Strategies do not size orders. Timed exits receive a distinct stable decision key so entry duplicate prevention does not suppress the normal exit. Current observations must be supplied at execution time; existing layers remain responsible for snapshot freshness, market precision, minimums, funded balances, gross exposure, duplicate prevention and risk reservation. No live submission is added.

Run `python -m kraken_quant.milestone1 connectivity` explicitly with dedicated `KRAKEN_READONLY_API_KEY` and `KRAKEN_READONLY_API_SECRET` in ignored `.env`. No generic/trading key fallback is allowed. The loader checks read-only permissions before private account reads and rejects a matching trading key. Authentication and balances do not query markets or access CONFIG.universe. Pair identity is resolved lazily only for a requested fee lookup; existing fee/risk instrument policy is preserved. Output contains success flags only, with private data and exchange exceptions suppressed. Never enable trading, deposit or withdrawal permissions on this key.

GitHub Actions pip caching hashes requirements-ci.txt, requirements-research.txt and requirements-notebook.txt, the same files installed by CI. No notebooks or environment snapshots are changed by this implementation; no locked test-period data is evaluated. Authentication and passing tests do not establish profitability or live readiness.
